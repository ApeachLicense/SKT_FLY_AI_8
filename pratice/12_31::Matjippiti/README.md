FLY AI WorkShop 마지막 날 진행되었던 RAG 기반 AI 에이전트 프로젝트 해커톤에서 다듬은 프롬프트에 대해서 정리한 리포지토리.

URL: https://github.com/SKT8LL/Matjippiti/watchers

ROLE : 에이전트가 사용자에게 맛집을 잘 추천해줄 수 있도록 프롬프트 query 작성. 초반에는 안그래도 프롬프트 query를 어떻게 적어야 될지 아예 갈피를 잡지 못하고 있었는데, 평가 지표에 재미가 들어있다고 해서 레스토랑 테마별로 에이전트의 말투에 차별점을 둬야되나(일식->'추천해준다능' 이런식으로) 고민했다.
그런데 마침 같이 프롬프트 역할을 배정 받은 사람이 흑백요리사2 얘기를 꺼내길래, 단순히 맛집을 추천해주기 보다는 에이전트가 요리 관련 유명인사를 모사하여(페르소나) 맛집을 추천해주면 좋을 것 같다고 팀원들에게 제안하였고, 그 제안이 컨펌되어서 그런쪽으로 프롬프트를 다듬어보았다.

초기에 준비한 페르소나는 '이븐하다'는 표현으로 유명한 안성재와 화끈한 욕설로 유명한 고든 램지였는데, 고든 램지 같은 경우 아무래도 고든 램지의 화법에 대해 자막을 단 사람들도 조금 씩 다른데다가 맛집 추천에서 고든 램지 특유의 욕설을 표현하기는 어려운 것 같아서. 기각되어 고든램지 페르소나는 폐기되고, 백종원 페르소나로 바뀌었다.

이 레포지토리에는 내가 다듬었던 고든램지 프롬프트와 안성재 프롬프트를 다듬었던 과정과 그 query를 저장해둔 디렉토리이다. 소스코드의 경우 URL을 타고 들어가서 열람할 수 있다.

후기: 
사실 맨 처음에는 에이전트에게 한국투자증권 모의투자를 시키려고 하였고, 이를 위해 팀장형이 API Key까지 미리 발급을 해놓은 상황이었다. 당일날에도 해당 토픽으로 에이전트를 준비하려고 하였고, 나는 'RAG 기술 사용'이라는 조건을 충족하기 위해서 버크셔 해서웨이의 주주서한(https://www.berkshirehathaway.com/letters/letters.html)을 RAG로 넣어서 투자 에이전트를 만들면 좋을 것 같다고 제안하였지만, 아쉽게도 시간관계상 주제가 맛집데이터.csv를 바탕으로 사용자의 상황(지역,가격,요리양식 등)에 알맞는 식당을 추천해주는 에이전트로 바뀌었다. 페르소나에게 제공할 고든램지와 안성재의 특징을 추출한 NoteBookLm도 Google이 RAG를 기반으로 만든 프로그램이니, 우리는 RAG 기술을 상당히 많이 사용한 셈이다. 기술하였다시피 고든램지는 도저히 시연할수 없는 상황이라서 안성재를 준비였다.
하지만, RAG개발이나 streamlit을 통한 시각화를 담당한 파트에서는 프롬프트를 깎은 환경에서처럼 안성재스러운 화법이 잘 드러나지 않아서 결국 시연할 페로소나로 말 끝에 '~유'를 붙여서 페르소나 구현이 쉬운 백종원으로 정해졌다. 나중에 확인해보니 우리가 전달한 프롬프트 텍스트가 제대로 전달되지 않아서 안성재스로운 화법이 실제 시연화면해서는 잘 나오지 않고 있었다. 아무튼, 나는 나름대로 값진 경험을 했다고 생각한다. LangChain으로 어떻게 사용자가 던저준 파일을 참조하여, 사용자에게 답변을 전달하는 에이전트를 만드는 지 구현하는 것도 좋지만, 사실 이런 개발은 학부중에서도 마음만 막으면 할 수 있는 일이라서 그 에이전트가 누구의 역할을 맡아야 되고, 이를 어떻게 학습시킬지를 고민하고, 이를 NoteBOOKLM이라는 Google의 RAG 기법 프로그램으로 페르소나 대상의 특징을 유튜브로 특징을 추출하고, 이를 에이전트에게 전달하는 역할은 매우 색다르고 재밌는 경험이었다. 그런데, 에이전트에게 특정 미식가의 맛칼럼 PDF를 던저주고, 에이전트가 해당 맛컬럼을 RAG한 다음, 사용자에게 사용자의 상황에 알맞는 식당을 추천해주면 어땠을까 싶다. API-key도 GPT가 아니라 검색에 특화된 Perplexity api- key를 써써 말이다.
