## Role: Prompt Engineer

**"사용자에게 즐거움을 주는 추천 에이전트 설계"**

처음에는 프롬프트 쿼리 작성의 방향성을 잡는 데 어려움이 있었으나, 해커톤 평가 지표에 **'재미'** 요소가 포함된 점에 주목했습니다. 단순한 정보 전달을 넘어 레스토랑 테마별로 에이전트의 말투에 차별점(예: 일식 -> '추천해준다능')을 두는 것을 고민했습니다.

그러던 중, **함께 프롬프트를 담당했던 동료와 논의**하는 과정에서 당시 화제였던 **'흑백요리사'** 이야기가 나왔고, **"안성재 셰프처럼 맛집을 추천해주면 어떨까?"**라는 아이디어를 얻게 되었습니다. 이를 구체화하여 **"유명 요리 인사의 페르소나를 에이전트에 입혀 맛집을 추천하자"**고 팀원들에게 제안하여 최종 채택되었습니다.

### Persona Development Process

이 리포지토리의 디렉토리에는 아래 페르소나들을 구현하기 위해 다듬었던 프롬프트와 쿼리 과정이 저장되어 있습니다.

1. **안성재 셰프 (The 'Even' Chef)**
* **컨셉**: 고기의 익힘 정도나 재료의 조화를 중요시하며 "이븐(Even)하다"라는 표현을 즐겨 쓰는 꼼꼼한 미식가.
* **상태**: 프롬프트 개발 완료.


2. **고든 램지 (The Hell's Kitchen)**
* **컨셉**: 화끈한 독설과 직설적인 화법.
* **폐기 사유(Drop)**: 자막 번역본마다 화법이 상이하여 통일된 데이터 확보가 어려웠고, 맛집 추천이라는 긍정적 맥락에서 특유의 비속어(욕설)를 적절히 구현하는 데 한계가 있어 기각되었습니다.


3. **백종원 대표 (The Business Genius)** - **[Final Selection]**
* **컨셉**: 친근한 충청도 사투리(~유)와 대중적인 입맛.
* **채택 사유**: 안성재 페르소나의 뉘앙스가 시스템 연동 과정에서 일부 희석되는 문제가 발생하여, 시연 시 확실한 캐릭터성을 보여줄 수 있는 백종원 페르소나로 최종 변경하였습니다.

## Retrospective (회고)

### 1. 주제 선정과 Pivot: 투자에서 미식으로

사실 초기 기획은 **'한국투자증권 모의투자 에이전트'**였습니다. 팀장님이 API Key까지 미리 발급받을 정도로 준비가 된 상태였고, 저는 **RAG(검색 증강 생성)** 기술 요건을 충족하기 위해 **[버크셔 해서웨이 주주서한](https://www.berkshirehathaway.com/letters/letters.html)**을 지식 베이스로 활용하여 워렌 버핏의 철학을 담은 투자 에이전트를 제안했습니다. 하지만 해커톤이라는 한정된 시간 내에 완성도를 높이기 위해, `맛집데이터.csv`를 기반으로 한 맛집 추천 에이전트로 주제를 변경하게 되었습니다.

### 2. 기술적 시도와 RAG의 활용 (NotebookLM)

비록 주제는 변경되었지만, RAG 기술 활용이라는 목표는 프롬프트 엔지니어링 과정에서 달성했습니다.
구글의 **NotebookLM(RAG 기반 도구)**을 활용하여 안성재 셰프와 고든 램지의 유튜브 영상 등 비정형 데이터에서 화법과 성격적 특징을 추출했습니다. 이를 통해 페르소나를 정교하게 다듬을 수 있었으며, 개발 과정에 RAG 기술을 적극적으로 녹여냈습니다.

### 3. 시행착오와 교훈

실제 개발 파트(RAG 및 Streamlit 시각화)와 프롬프트를 통합하는 과정에서, 제가 의도했던 '안성재스러운' 미묘한 화법이 완벽하게 전달되지 않는 이슈가 있었습니다. 결국 시연 효과를 위해 어미 처리(~유)만으로도 구현이 용이한 백종원 페르소나를 선택하게 되었습니다.

이번 프로젝트를 통해 얻은 가장 값진 경험은 '구현' 그 자체보다 **'설계'의 중요성**을 깨달은 것입니다. LangChain으로 문서를 참조해 답변하는 기능은 학부생 수준에서도 충분히 구현할 수 있습니다. 하지만 **"이 에이전트가 누구의 역할을 맡아야 하는가?", "어떻게 그 특징을 학습시키고 전달할 것인가?"**를 고민하고, NotebookLM과 같은 최신 도구를 활용해 페르소나를 구체화하는 과정은 훨씬 창의적이고 색다른 경험이었습니다.

### 4. Future Improvements

만약 다시 진행한다면, 에이전트에게 특정 미식가의 맛 칼럼 PDF를 RAG로 연동하고, 일반적인 LLM API 대신 검색에 특화된 **Perplexity API**를 활용해보고 싶습니다. 이를 통해 단순 추천을 넘어, 사용자의 상황에 맞춰 실제 칼럼니스트가 분석해 주는 듯한 깊이 있는 추천 서비스를 만들 수 있을 것입니다.
